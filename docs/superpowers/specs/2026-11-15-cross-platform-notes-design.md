# เอกสารออกแบบ: แอปจดโน้ตและขีดเขียนเอกสารข้ามแพลตฟอร์ม (แนว Goodnotes)

วันที่: 2026-11-15

## 1. เจตนาและเหตุผล

ต้องการแอปจดโน้ตด้วยลายมือแบบ Goodnotes ที่ใช้ได้ทุกแพลตฟอร์ม (iPad, Android, Windows, macOS, เว็บ)
ให้ผู้ใช้หลายคนเขียนข้อมูลเพิ่มเติมลงบนเอกสาร (PDF, หน้าเว็บที่บันทึกเข้ามา, รูปภาพ) และสมุดเปล่า
โดย **ข้อมูลทั้งหมดเก็บในเครื่องของผู้ใช้แต่ละคน** ไม่มีเซิร์ฟเวอร์กลาง
บริบทการใช้งานน่าจะรวมถึงเอกสารงานราชการ/คดี จึงให้ความสำคัญกับความเป็นส่วนตัวของข้อมูล

## 2. เป้าหมาย (v1)

1. **โปรไฟล์ผู้ใช้หลายคนต่อเครื่อง** — เลือกโปรไฟล์ตอนเปิดแอป, ล็อกด้วย PIN, ข้อมูลแต่ละโปรไฟล์แยกขาดจากกัน
2. **นำเข้าเอกสาร**: PDF, รูปภาพ (JPG/PNG/HEIC→แปลง), และ **หน้าเว็บ** (วางลิงก์ → แอปเรนเดอร์หน้าเว็บเป็น PDF แล้วเก็บเป็นเอกสาร)
3. **สมุดเปล่า**: กระดาษเปล่า / มีเส้น / ตาราง, ขนาด A4 แนวตั้งเป็นค่าเริ่มต้น, เพิ่ม/ลบ/สลับหน้าได้
4. **การป้อนข้อมูล 3 โหมด (สลับจากแถบเครื่องมือ)**
   - **โหมดปากกา (stylus)**: รับเฉพาะ `pointerType === "pen"` ในการวาด, รองรับแรงกด, นิ้ว/ฝ่ามือใช้เลื่อน-ซูมเท่านั้น (กันฝ่ามือ)
   - **โหมดเขียนด้วยมือ (นิ้ว)**: นิ้วเดียวเขียน, สองนิ้วเลื่อน/ซูม; แรงกดจำลองจากความเร็ว
   - **บันทึกเสียง**: แตะตำแหน่งบนหน้า → อัดเสียง → วางไอคอนเสียงที่จุดนั้น แตะเพื่อเล่น/ลบ (เก็บเฉพาะไฟล์เสียง ไม่ถอดความ)
   - บนเดสก์ท็อป เมาส์ถือเป็นปากกา
5. **เครื่องมือเขียน**: ปากกา, ปากกาเน้นข้อความ (โปร่งแสง, วาดใต้หมึก), ยางลบแบบลบทั้งเส้น, เลือกแบบบ่วงบาศ (lasso) เพื่อย้าย/ลบ, Undo/Redo
   - **ปรับแต่งปากกาละเอียด** (เพิ่มตามคำขอ): สี (จานสี + กำหนดเอง), ความหนา (0.2–20 pt แบบเลื่อนละเอียด), ความไวแรงกด (กราฟ 3 ระดับ + ปิดแรงกด), ความเรียวปลายเส้น (เริ่ม/จบ), ความโปร่งใส, การทำให้เส้นเรียบ (smoothing); บันทึกเป็น **ปากกาโปรด** ได้สูงสุด 10 อัน สลับด้วยแตะเดียว
   - **ขีดฆ่าเพื่อลบ (scribble to erase)** (เพิ่มตามคำขอ): ขีดซิกแซกทับเส้นเดิม ≥3 กลับทิศภายในเส้นเดียว → ลบเส้นที่ถูกทับ (ซ่อนตามกฎ audit) + แสดงแอนิเมชันสั้น ๆ; เปิด/ปิดได้ในตั้งค่า
   - **วาดรูปทรงอัตโนมัติ** (เพิ่มตามคำขอ): วาดค้างไว้ 0.5 วินาทีเมื่อจบเส้น → แปลงเป็นเส้นตรง / ลูกศร / วงกลม / วงรี / สี่เหลี่ยม / สามเหลี่ยม (ใช้ตัวจำแนกเชิงเรขาคณิตแบบในเครื่อง เช่น $1/$P recognizer + การฟิตเส้น) ; Undo กลับเป็นเส้นมือได้
6. **กล่องพิมพ์ข้อความ** (เพิ่มตามคำขอ): แตะด้วยเครื่องมือ "T" → พิมพ์ข้อความบนหน้า, ย้าย/ปรับขนาดได้, ฟอนต์ไทยฝังในแอป (Sarabun/TH Sarabun New), ขนาด/สี/ตัวหนา; ส่งออกเป็นข้อความจริงใน PDF (คัดลอก/ค้นหาได้)
7. **OCR ตัวพิมพ์ในเอกสารสแกน** (เพิ่มตามคำขอ): เมื่อนำเข้า PDF/รูปที่ไม่มีชั้นข้อความ ให้รัน **Tesseract (WASM) ภาษาไทย+อังกฤษในเครื่อง** เบื้องหลังทีละหน้า → เก็บชั้นข้อความพร้อมตำแหน่งคำ; ค้นหาคำในเอกสารเดียวและทั้งห้องสมุด, ไฮไลต์ผลบนหน้า; ส่งออก PDF แบบมีชั้นข้อความที่ค้นหาได้ (เลือกได้); PDF ที่มีข้อความอยู่แล้วใช้ข้อความเดิมจาก pdf.js ไม่ต้อง OCR; ไม่ OCR ลายมือ
8. **แถบเครื่องมือย่อเก็บได้** (เพิ่มตามคำขอ): แถบเครื่องมือย่อเป็นปุ่มเดียวได้, ลาก/ติดขอบ บน-ล่าง-ซ้าย-ขวา, โหมดอ่านเต็มจอซ่อนทุกปุ่ม (แตะ 3 นิ้วหรือปุ่มเดียวเพื่อสลับ), จำตำแหน่งต่อขนาดจอ — แก้ปัญหาปุ่มบังพื้นที่บนจอเล็ก
9. **การจัดระเบียบ**: โฟลเดอร์ → เอกสาร/สมุด, ภาพย่อหน้าปก, ค้นหาตามชื่อเอกสารและข้อความ OCR/กล่องข้อความ
10. **ส่งออก/แบ่งปัน** (ช่องทางเดียวที่ข้อมูลออกนอกเครื่อง):
   - PDF รวมรอยเขียน (flatten) — สำหรับส่งให้ผู้อื่น/พิมพ์
   - ไฟล์ชุดโน้ต `.pnote` (zip: ต้นฉบับ + ชั้นรอยเขียน + เสียง + metadata) — สำหรับย้ายเครื่อง/สำรอง/ส่งให้เพื่อนร่วมงานที่ใช้แอปนี้ นำเข้าแล้วแก้ต่อได้
11. **ใช้งานออฟไลน์ได้ 100%** (ไฟล์ภาษา Tesseract ไทย ~1–4 MB และฟอนต์ไทยรวมมากับแอป ไม่โหลดจากเน็ต)

## 3. สิ่งที่ไม่ทำใน v1 (Non-goals)

- ซิงก์ผ่านคลาวด์ / ทำงานร่วมกันแบบเรียลไทม์
- ถอดเสียงเป็นข้อความ (ออกแบบให้เพิ่ม Whisper แบบในเครื่องภายหลังได้ — เก็บเสียงเป็นไฟล์แยกพร้อม id)
- ค้นหาลายมือ (handwriting OCR) และแปลงลายมือเป็นตัวพิมพ์ — ไม่มีโมเดลลายมือไทยแบบออฟไลน์ที่แม่นพอ (รุ่นถัดไป)
- ไวท์บอร์ดไม่มีขอบเขต (infinite whiteboard) — รุ่นถัดไป
- AI สรุปเนื้อหา / ถาม-ตอบ — รุ่นถัดไป และต้องทำในเครื่องเท่านั้น
- ขีดเขียนบนเว็บจริงขณะท่อง (browser extension)
- เปิด Word/Excel/PowerPoint โดยตรง — v1 ให้ผู้ใช้แปลงเป็น PDF ก่อน (ใน Tauri เดสก์ท็อป ถ้าพบ LibreOffice ติดตั้งอยู่ ให้แปลงอัตโนมัติได้ — เป็นของแถม ไม่บังคับ)
- สติกเกอร์, คลังเทมเพลตเพิ่มเติม (นอกจากกระดาษเปล่า/เส้น/ตาราง)

## 4. Anti-goals (ถ้าเกิดสิ่งนี้ ถือว่าล้มเหลวแม้จะทำงานได้)

- ข้อมูล (เอกสาร/รอยเขียน/เสียง) ถูกส่งออกนอกเครื่องโดยผู้ใช้ไม่ได้กดส่งออกเอง — ห้ามมี analytics/telemetry/CDN runtime ที่ส่งข้อมูลผู้ใช้
- เส้นหมึกตามปากกาไม่ทัน (เป้าหมาย: เส้นปรากฏภายใน 1 เฟรม ~16ms บน iPad รุ่นปี 2020+)
- **ไฟล์ต้นฉบับถูกแก้ไข** — ต้นฉบับต้องคงเดิมเสมอ (เก็บ SHA-256 ไว้ตรวจสอบ) รอยเขียนเป็นชั้นแยก
- โปรไฟล์หนึ่งเห็นข้อมูลของอีกโปรไฟล์

## 5. ข้อจำกัด

- ไม่มีเซิร์ฟเวอร์ ข้อมูลอยู่ในเครื่องเท่านั้น
- เว็บ (PWA) ดึงหน้าเว็บข้ามโดเมนไม่ได้ (CORS) → การนำเข้าหน้าเว็บด้วย URL ทำได้เฉพาะในแอปที่ห่อด้วย Capacitor/Tauri; ใน PWA ให้ใช้ "พิมพ์เป็น PDF/แชร์" แล้วนำเข้า PDF
- iOS Safari อาจล้างพื้นที่เก็บของ PWA ที่ไม่ได้ใช้นาน → PWA ต้องเรียก `navigator.storage.persist()` และเตือนให้สำรอง `.pnote`; แอป iPad ที่ใช้จริงควรเป็นเวอร์ชัน Capacitor
- การติดตั้งบน iPad ต้องผ่าน Apple Developer Program (TestFlight / App Store / ไม่ลงสาธารณะ)
- ผู้พัฒนาคุ้นเคย JavaScript/Google Apps Script — เลือกเทคโนโลยีฝั่ง JS/TS

## 6. แนวทางที่พิจารณา

| แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| 1. PWA อย่างเดียว | โค้ดชุดเดียว, เปิดจากลิงก์ได้ทันที | นำเข้าเว็บด้วย URL ไม่ได้, iOS เสี่ยงข้อมูลถูกล้าง |
| 2. Flutter native | หมึกลื่นที่สุด, ไฟล์ถาวร, ดึงเว็บได้ | ต้องเรียน Dart, เขียนใหม่ทั้งหมด |
| **3. แกนเว็บ TS + ห่อ Capacitor (iOS/Android) + Tauri (Windows/macOS)** ✅ | JS ชุดเดียว, ได้ PWA ก่อน, ห่อเป็นแอปแก้ CORS/พื้นที่เก็บ | build หลายชุด, หมึกลื่นน้อยกว่า native เล็กน้อย |

**ผู้ใช้เลือกแนวทางที่ 3** — ตัดสินใจแล้ว
Google Apps Script ถูกตัดออก: HtmlService อยู่ใน iframe sandbox, ทำงานออฟไลน์ไม่ได้, เก็บข้อมูลในเครื่องไม่ได้

## 7. สิ่งที่ผู้ใช้ตัดสินใจแล้ว

- ผู้ใช้หลายคน, เก็บข้อมูลในเครื่องของแต่ละคน
- เขียนเพิ่มบน PDF และหน้าเว็บ — หน้าเว็บใช้วิธี **วางลิงก์แล้วบันทึกเป็นเอกสาร** (ไม่ใช่ extension)
- โหมดแยก: เขียนด้วยมือ / เขียนด้วยปากกา / บันทึกเสียง
- บันทึกเสียง: **เก็บเสียงอย่างเดียว** ไม่ถอดความ
- สถาปัตยกรรม: แนวทางที่ 3
- ความปลอดภัย: ต้องกันกรณี **เครื่องหาย/ถูกยึด** ด้วย

## 8. การออกแบบ (ข้อเสนอของผู้ออกแบบ — ผู้ใช้แก้ได้)

### 8.1 สถาปัตยกรรม

```
apps/
  web/        ← PWA (Vite + TypeScript) — แกนหลัก, ใช้ทดสอบเร็ว
  mobile/     ← Capacitor ห่อ web build (iOS, Android)
  desktop/    ← Tauri 2 ห่อ web build (Windows, macOS)
packages/
  core/       ← โมเดลข้อมูล, เอกสาร, undo/redo, export/import (ไม่ผูก UI/แพลตฟอร์ม)
  ink/        ← รับ pointer events, สร้างเส้น, เรนเดอร์ canvas
  storage/    ← interface StorageAdapter + implementation ต่อแพลตฟอร์ม
  platform/   ← interface PlatformBridge (นำเข้าเว็บ, เลือกไฟล์, แชร์, ไมโครโฟน)
```

UI ใช้ framework เบา (แนะนำ **Svelte** หรือ Preact — ผู้สร้างเลือกได้) แต่ส่วนวาดหมึกเป็น canvas ตรง ไม่ผ่าน virtual DOM

### 8.2 โมเดลข้อมูล

- `Profile { id, name, avatarColor, pinSalt, pinVerifier, createdAt }`
- `Folder { id, profileId, parentId, name }`
- `Document { id, profileId, folderId, title, kind: "pdf"|"image"|"web"|"notebook", sourceBlobId?, sourceSha256?, sourceUrl?, capturedAt?, pages: PageRef[], createdAt, updatedAt }`
- `PageRef { id, index, source: {type:"pdf", pageNo} | {type:"blank", template:"plain"|"lined"|"grid"} | {type:"image", blobId}, widthPt, heightPt }`
- `Stroke { id, pageId, tool:"pen"|"highlighter", color, width, points: Float32Array [x,y,pressure,t]*, input:"pen"|"touch"|"mouse", authorProfileId, authorName, hidden?, createdAt }`
- `AudioNote { id, pageId, x, y, blobId, mime, durationMs, authorProfileId, authorName, createdAt }`
- `Shape { id, pageId, kind:"line"|"arrow"|"ellipse"|"rect"|"triangle", geometry, penStyle, sourceStrokeId, authorProfileId, authorName, hidden?, createdAt }`
- `TextBox { id, pageId, x, y, w, h, text, font, sizePt, color, bold, authorProfileId, authorName, hidden?, createdAt, updatedAt }`
- `OcrPage { pageId, engine:"tesseract"|"pdf-text", lang, words:[{text, bbox, conf}], doneAt }`
- `PenPreset { id, profileId, name, tool, color, width, opacity, pressureCurve, taperStart, taperEnd, smoothing }`
- `AuditEntry { seq, time, profileId, profileName, action, objectId, prevHash, hash }` (ดูข้อ 8.5.1)
- พิกัดทั้งหมดเป็น **หน่วย point ของหน้า (PDF space)** ไม่ขึ้นกับระดับซูม/ขนาดจอ
- รอยเขียนเก็บแยกต่อหน้า (`page-<id>.strokes`) เพื่อโหลด/บันทึกเร็ว

### 8.3 การเขียนหมึก

- Pointer Events + `getCoalescedEvents()` + `getPredictedEvents()` ลดความหน่วง
- ใช้ไลบรารี **perfect-freehand** สร้างรูปเส้นจาก [x,y,pressure]
- Canvas 2 ชั้นต่อหน้า: ชั้น "เส้นที่กำลังวาด" (วาดทุกเฟรม) และชั้น "เส้นที่บันทึกแล้ว" (cache เป็น bitmap); PDF เรนเดอร์ด้วย **pdf.js** เป็นชั้นล่างสุด, เรนเดอร์ซ้ำเมื่อซูมเปลี่ยนแบบหน่วงเวลา
- `touch-action: none` บนพื้นที่วาด; การเลื่อน/ซูมจัดการเอง
- โหมดปากกา: pen = วาด, touch = เลื่อน/ซูม; โหมดนิ้ว: 1 นิ้ว = วาด, 2 นิ้ว = เลื่อน/ซูม
- Undo/Redo: command stack ต่อเอกสาร (เพิ่มเส้น, ลบเส้น, ย้ายเส้น, เพิ่ม/ลบเสียง, จัดหน้า), ล้างเมื่อปิดเอกสาร
- บันทึกอัตโนมัติ: หลังจบเส้น debounce 500ms

### 8.4 การเก็บข้อมูลและความปลอดภัย

- `StorageAdapter` (get/put/delete/list blob + JSON):
  - เว็บ: IndexedDB (metadata) + OPFS (blob ใหญ่: PDF, เสียง)
  - Capacitor: `@capacitor/filesystem` (Directory.Data) + SQLite หรือไฟล์ JSON
  - Tauri: `appDataDir()` ผ่าน `@tauri-apps/plugin-fs`
- โครงสร้าง: `/<profileId>/documents/<docId>/{meta.json, source.pdf, pages/*.strokes, audio/*.m4a}`
- **ความปลอดภัย — ผู้ใช้ตัดสินใจแล้ว: ต้องกันกรณีเครื่องหาย/ถูกยึดด้วย** (ไม่ใช่แค่กันคนใช้เครื่องร่วมกัน)
  - แต่ละโปรไฟล์มี **Data Key** (AES-GCM-256 สุ่ม) เข้ารหัส blob และ JSON ทั้งหมดของโปรไฟล์
  - Data Key ถูกห่อ (wrap) ด้วยกุญแจ 2 ชั้น: (1) กุญแจจากฮาร์ดแวร์ของเครื่อง — iOS/macOS Keychain + Secure Enclave, Android Keystore (StrongBox ถ้ามี), Windows DPAPI/TPM — ไม่สามารถดึงออกจากเครื่องได้; (2) กุญแจจาก PIN/รหัสผ่านผ่าน Argon2id (หรือ PBKDF2-SHA256 ≥600,000 รอบถ้าไม่มี Argon2)
  - สำเนาไฟล์ที่ถูกคัดลอกออกจากเครื่องจึงถอดรหัสไม่ได้แม้เดา PIN ครบทุกค่า
  - **จำกัดการใส่ PIN ผิด**: ผิด 5 ครั้ง → หน่วงเวลาเพิ่มขึ้นเรื่อย ๆ; ผิด 10 ครั้ง → ล็อกโปรไฟล์ (ต้องปลดด้วยรหัสกู้คืน)
  - ตอนสร้างโปรไฟล์ แอปออก **รหัสกู้คืน 24 ตัวอักษร** ให้จดเก็บ (ห่อ Data Key อีกชุด) — ลืมทั้ง PIN และรหัสกู้คืน = ข้อมูลหาย
  - **PWA** ไม่มีกุญแจฮาร์ดแวร์: ใช้รหัสผ่านอย่างน้อย 8 ตัวอักษร (ไม่ใช่ PIN 6 หลัก) + Argon2id (WASM), แสดงป้ายเตือนว่า "เวอร์ชันเว็บ ความปลอดภัยต่ำกว่าแอปติดตั้ง" — แอปติดตั้งเป็นตัวหลักสำหรับข้อมูลคดี
  - **ไฟล์ส่งออกเข้ารหัสเสมอ**: `.pnote` เข้ารหัสด้วยรหัสผ่านที่ตั้งตอนส่งออก; PDF ส่งออกเลือกได้ว่าจะใส่รหัสผ่าน PDF หรือไม่ โดยแสดงคำเตือนชัดเจนเมื่อเลือกไม่ใส่
  - ล็อกอัตโนมัติหลังไม่ใช้งาน 5 นาที (ตั้งค่าได้), ล้างกุญแจออกจากหน่วยความจำเมื่อล็อก, ซ่อนเนื้อหาในภาพตัวสลับแอป (app switcher)
  - เข้ารหัสเป็นช่วง (chunk 1 MB, AES-GCM ต่อ chunk) เพื่อให้ PDF ขนาดใหญ่โหลดเฉพาะส่วนที่ต้องการได้

### 8.5 การนำเข้า

- PDF / รูปภาพ: ตัวเลือกไฟล์ของระบบ, ลากวาง (เดสก์ท็อป), "แชร์มาที่แอป" (มือถือ — share target)
- **หน้าเว็บ** (`PlatformBridge.captureWebPage(url) → PDF blob`):
  - iOS: WKWebView โหลด URL → `createPDF` (Capacitor plugin เขียนเอง, Swift)
  - Android: WebView → `PrintDocumentAdapter` เขียนเป็น PDF (plugin Kotlin)
  - Windows: WebView2 `PrintToPdfAsync`; macOS: WKWebView `createPDF` (Tauri plugin Rust/คำสั่ง native)
  - เว็บ PWA: แสดงคำแนะนำให้ใช้ "พิมพ์ → บันทึกเป็น PDF" แล้วนำเข้า
  - เก็บ `sourceUrl` และ `capturedAt` ไว้ในเอกสาร แสดงเป็นหัวกระดาษในแอป (มีประโยชน์ด้านหลักฐาน)
  - หน้าที่ต้องล็อกอิน: WebView ที่ใช้ capture แสดงให้ผู้ใช้เห็นและล็อกอินเองได้ก่อนกด "บันทึก"

### 8.5.1 ระดับพยานหลักฐาน (สมมติฐานของผู้ออกแบบ — ผู้ใช้ยังไม่ได้ยืนยัน)

สมมติว่าเอกสารต้องใช้อ้างอิงเป็นพยานหลักฐานได้ จึงออกแบบดังนี้ตั้งแต่ v1:
- **ตอนบันทึกหน้าเว็บ** เก็บ 4 อย่างคู่กัน: PDF, ภาพหน้าจอทั้งหน้า (PNG), HTML/MHTML ต้นฉบับ, และ `capture.json` (URL ที่ขอ, URL สุดท้ายหลัง redirect, เวลาเครื่อง + timezone, user agent, SHA-256 ของทั้ง 3 ไฟล์)
- **ตอนนำเข้าไฟล์ทุกชนิด**: คำนวณ SHA-256 ต้นฉบับทันที, เก็บชื่อไฟล์เดิม, เวลานำเข้า
- **บันทึกการแก้ไขแบบเพิ่มอย่างเดียว (append-only audit log)** ต่อเอกสาร: ทุกการเพิ่ม/ลบ/ย้ายเส้น, เสียง, หน้า บันทึก `{seq, time, profileId, profileName, action, objectId, prevHash}` แบบ hash chain — แก้ย้อนหลังแล้วตรวจจับได้; การ "ลบ" เส้นเป็นการซ่อน ไม่ลบข้อมูลจริง
- `Stroke` และ `AudioNote` มีฟิลด์ `authorProfileId`, `authorName`
- **PDF ที่ส่งออก** มีหน้าท้าย "ข้อมูลรับรองเอกสาร": ชื่อเอกสาร, แหล่งที่มา/URL, เวลานำเข้า/บันทึก, SHA-256 ต้นฉบับ, ผู้เขียน, จำนวนการแก้ไข, hash ล่าสุดของ audit log; และมีส่วนหัว/ท้ายกระดาษเล็ก ๆ แสดง URL และเวลาบันทึกบนหน้าเว็บที่ส่งออก
- ข้อจำกัดที่ต้องแจ้งผู้ใช้: เวลามาจากนาฬิกาเครื่อง (ไม่มี timestamp server เพราะข้อมูลไม่ออกนอกเครื่อง)

### 8.5.2 ไฟล์ `.pnote` (การตัดสินใจของผู้ออกแบบ)

- มี 2 แบบ: **เอกสารเดียว** (ส่งให้เพื่อนร่วมงาน) และ **สำรองทั้งโปรไฟล์**
- เอกสารมี id ถาวรข้ามเครื่อง; เมื่อนำเข้าเอกสารที่มี id ซ้ำ ให้เลือก "นำเข้าเป็นสำเนาใหม่" (ค่าเริ่มต้น) หรือ "แทนที่ของเดิม" — ไม่ merge เส้นอัตโนมัติใน v1
- audit log และผู้เขียนเดินทางไปกับไฟล์ ผู้รับเขียนต่อได้และ log ต่อท้ายด้วยชื่อผู้รับ

### 8.6 บันทึกเสียง

- `MediaRecorder` (เว็บ/Android: `audio/webm;codecs=opus`, iOS: `audio/mp4`); ใน Capacitor ถ้า MediaRecorder ไม่เสถียร ใช้ plugin บันทึกเสียง native
- ขอสิทธิ์ไมโครโฟนเมื่อใช้ครั้งแรก, แสดงตัวจับเวลาและปุ่มหยุด, จำกัด 30 นาทีต่อคลิป
- ส่งออก PDF: ไอคอนเสียงแสดงเป็นรูปบนหน้า; ไฟล์เสียงฝังเป็น PDF file attachment annotation (ถ้าทำได้ด้วย pdf-lib) และอยู่ครบใน `.pnote`

### 8.7 การส่งออก

- PDF flatten ด้วย **pdf-lib**: วาดเส้นเป็น vector path บนหน้า PDF ต้นฉบับ (ไม่ rasterize)
- `.pnote` = zip (JSZip/fflate) + `manifest.json` (version, รายการไฟล์, SHA-256 ต้นฉบับ)

### 8.9 ลำดับการส่งมอบ (สมมติฐาน — ผู้ใช้ยังไม่ได้ระบุแพลตฟอร์มหลัก)

สมมติว่าใช้ปนกันหลายแบบ จึงเริ่มจากแกนร่วม แต่ทดสอบหมึกบน iPad + Android จริงตั้งแต่ขั้นที่ 1 และย้ายแอปติดตั้งขึ้นมาก่อน เพราะความปลอดภัยระดับเครื่อง (ข้อ 8.4) ทำได้เต็มที่เฉพาะในแอปติดตั้ง:
1. แกน + PWA (dev build): โปรไฟล์, สมุดเปล่า, หมึก 2 โหมด, เครื่องมือ + ปากกาปรับละเอียด/ปากกาโปรด, แถบเครื่องมือย่อเก็บได้, ขีดฆ่าเพื่อลบ, รูปทรงอัตโนมัติ, บันทึกอัตโนมัติ, audit log
2. PDF: นำเข้า, เรนเดอร์ (รองรับไฟล์ใหญ่), เขียนทับ, กล่องข้อความ, OCR ตัวพิมพ์ + ค้นหา, ส่งออก PDF + หน้ารับรอง
3. Capacitor Android + iOS: กุญแจฮาร์ดแวร์, PIN จำกัดครั้ง, capture หน้าเว็บ, `.pnote` (เข้ารหัสด้วยรหัสผ่าน) สำรอง/ย้ายเครื่อง — ย้ายมาจากขั้นที่ 4 ตามที่ผู้ใช้ขอ
4. บันทึกเสียง, PDF ที่ส่งออกแบบมีรหัสผ่าน
5. Tauri Windows/macOS + capture หน้าเว็บ + DPAPI/Keychain

PWA: เป็นไฟล์ static ล้วน วางบนโฮสต์ใดก็ได้ (เช่น GitHub Pages หรือเซิร์ฟเวอร์ในหน่วยงาน) — โฮสต์ส่งเฉพาะตัวโปรแกรม ไม่เห็นข้อมูลผู้ใช้; ใช้สำหรับทดสอบและเครื่องที่ติดตั้งโปรแกรมไม่ได้
iOS: ต้องมีบัญชี Apple Developer (บุคคล/องค์กร) ก่อนถึงขั้นที่ 3 — **ผู้ใช้ต้องจัดเตรียม**

## 9. สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ

- UI framework (Svelte/Preact), state management, ไลบรารี zip
- รายละเอียดการ cache/tiling ของ pdf.js เพื่อประสิทธิภาพ
- โครง CI/build, การเซ็นแอป
- ชุดสี/ความหนาปากกาเริ่มต้น, ไอคอน, ธีม (รองรับภาษาไทยเป็นภาษาหลักของ UI)
- รูปแบบการทดสอบ (แนะนำ unit test ส่วน core/storage + ทดสอบการเขียนบนอุปกรณ์จริง)
